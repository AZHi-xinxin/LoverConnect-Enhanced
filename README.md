# 💜 LoverConnect

## 2.4.1：跨机型、围栏与后台恢复修复

本修订恢复一个 APK 覆盖全安卓的运行时分流：Vivo 保留已验证的被动无障碍兼容模式；OPPO 使用保守生命周期诊断但保留主动应用锁与 RikkaHub 跳转；小米等其他 Android 继续使用标准主动路径。安全围栏改为约每 30 秒确认一次，连续三次可靠样本后立即发送；并修复从一个围栏直接切换到工作或自定义围栏时，到达事件因会话 ID 格式错误而被服务端拒绝的问题。

MCP 服务现在会记住手机用户的运行选择：已启用时可在开机和覆盖更新后自动恢复；用户明确点击“停止服务”后不会被旧自救闹钟偷偷拉起。全新安装默认由用户手动启动。公开版只包含通用 LC/MCP 能力，不包含任何私有记忆系统的签发界面或协议实现。

> 一个专为陪伴型AI设计的 Android MCP 工具App～
> 让你的AI伴侣能「感知」你的手机状态，真正陪在你身边 🐾

## ✨ 这是什么？

LoverConnect（简称LC）是一个运行在手机后台的小工具，通过 MCP 协议把你的手机状态暴露给AI聊天平台（比如 RikkaHub）。

简单来说：装上它，你的AI就能知道你的手机电量、今天走了多少步、在用什么App、外面天气怎么样……像一个真正关心你的人一样 💕

## 📦 安装使用

### 1. 安装App

下载最新版APK安装到手机上～

### 2. 授权权限

打开App后点击各项权限按钮完成授权：
- 使用情况访问权限
- 电池优化白名单
- 通知权限
- 体力活动权限
- 自启动管理

小L像素观察按系统版本使用两条相互隔离的路径：Android 11 及以上继续使用系统无障碍截屏，不需要投屏授权；Android 8–10 只有在手机用户主动点击「授权旧版 Android 屏幕捕获」并同意系统投屏弹窗后才启用。旧版 Android 的授权只保存在当前服务会话内，手机重启、应用进程结束、更新安装或用户停止共享后需要重新授权，运行期间会显示常驻通知。

### 3. 连接你的AI平台

LC 启动后会在首页显示并可复制一条本机私密 MCP 地址，格式类似：

`http://127.0.0.1:5000/mcp/<每次安装独有的随机令牌>`

在聊天平台（如 RikkaHub）里添加 MCP 连接时，请复制 App 实际显示的完整地址；不要照抄上面的示例，也不要把完整地址发给其他人。

2.4.x 只监听手机本机回环地址，拒绝浏览器 Origin，并要求每次安装独有的随机路径令牌；这是为了避免设备情境和可选通知摘要被同一网络或同机其他普通 App 直接读取。同一公开签名的覆盖安装会保留这条地址和应用设置；只有从尚未使用随机路径令牌的旧版本首次升级时，才需要在 RikkaHub 中重新复制一次地址。

## ⚠️ 注意事项

- **后台保活**：国产手机（OPPO、vivo、小米等）需要手动设置允许后台运行、关闭电池优化，不然App会被系统杀掉连不上
- **OPPO用户**：建议设置「允许完全后台行为」，实在不行就挂个小窗（很小几率），不然MCP连接会断
- **天气功能**：需要在App里设置你的城市名
- **纪念日**：在App里手动添加你们的重要日子～

### 2.4 设备情境与双通道

设备情境默认关闭，由手机用户在界面中自行开启。开启后，LC 可短时记录手机姿态、移动、环境光、距离传感器、屏幕、电量、前台应用等**设备事实**。通知摘要和经基础遮盖的通知文字各自还有独立开关；通知只存在当前进程内，最多返回最近30分钟，关闭相关开关会立即清除或剥离文字。通知字段始终标为不可信外部内容，不能被当作给 AI 的指令。

LC 不把“手机平放”解释成“用户躺下”，也不判断用户是否睡着、当前操作者身份、情绪或意图。完整设计与 AI 客户端接入边界见 [`DEVICE-CONTEXT.md`](DEVICE-CONTEXT.md)。

- **静默上下文**：供已获用户授权的 AI 客户端在下一次真实对话生成时读取，不会制造一条前台“提醒消息”。
- **主动唤醒**：重要事件继续使用现有哨兵链路，能够在用户没有先说话时叫醒 AI；当前 RikkaHub 正式接口会留下可见触发消息。
- 两者不能互相替代。只做静默注入，就必须等下一次对话；只做哨兵，则会在聊天前台留下触发文字。

### 2.4 自愿安全位置播报

除“家 / 工作”外，2.4 还可添加一个由手机用户自己命名的安全围栏，例如“健身房”或“朋友家”。围栏判断完全在手机本地完成，
安全区坐标使用 Android Keystore 加密保存；服务器只接收“确认离开、确认到达、
距离档位、暂停或定位降级”等结构化事件，默认不接收原始经纬度。

此功能默认关闭，必须由手机用户亲自授权精确/后台定位、设置安全区并开启前台服务。
自定义名称属于用户配置的数据，没有指令权限；AI/MCP 可以读取名称和区域状态，但不能读取坐标或静默改写围栏。
它只是一种生活提醒与平安播报，不是隐蔽追踪或紧急救援系统。部署与隐私边界见
[`LOCATION-SAFETY.md`](LOCATION-SAFETY.md)。

围栏采样目标周期为 30 秒；首次观察到变化后，还需累计三次满足精度、时间顺序和间隔要求的连续样本（通常约 60–90 秒）才确认。确认产生事件后立即进入耐久队列并触发发送，不再额外等待旧版的服务端宽限时间。

## ⚠️ Vivo / OPPO 运行时分流说明

同一个 APK 会读取 Android 提供的不可变 manufacturer/brand 身份做运行时分流；没有用户开关，AI 也不能修改。Vivo 上曾实测到主动回调会导致「小L无障碍」被系统回收，因此继续使用被动兼容策略。OPPO 真机未复现该故障，保留保守生命周期诊断的同时启用主动拦截；小米等其他 Android 使用标准主动路径。

- **所有分支保留**：小L定时截屏与视觉分析、前台应用与连续使用时长的被动记录、主动通知、哨兵告状、`get_l_service_status` 诊断读取，以及电量/步数/天气/纪念日/音乐/安全位置等全部其余功能。Android 11 及以上沿用无障碍像素截图；Android 8–10 使用手机用户明确授权、仅当前会话有效的 MediaProjection 截图，不会把授权令牌写入配置或备份。
- **OPPO 主动兼容**：应用锁、锁定浮层、返回桌面以及 RikkaHub 强制停留/定时跳转走主动路径；生命周期状态仍标为 `OEM_CONSERVATIVE`，便于持续观察厂商系统稳定性。
- **Vivo 暂不支持主动干预**：应用锁拦截、全屏锁定浮层、返回桌面、强制停留/定时跳转 RikkaHub 继续暂停，避免再次触发无障碍授权回收。
- **如实返回**：在 Vivo 被动分支调用 `lock_app`、`focus_rikka`、`redirect_to_rikka` 不会假装成功——MCP 会明确返回兼容模式暂不支持且不写入任何配置；`unlock_app` / `list_locked_apps` 仍可用于查看和清理历史锁定配置。

`get_l_service_status` 会返回当前 stability/intervention mode，便于真机确认分支。以上限制在 README、Release Notes 与 MCP 工具描述中保持一致。
